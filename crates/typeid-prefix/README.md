# `TypeID` Prefix

[![Crates.io](https://img.shields.io/crates/v/typeid_prefix.svg)](https://crates.io/crates/typeid_prefix)
[![Documentation](https://docs.rs/typeid_prefix/badge.svg)](https://docs.rs/typeid_prefix)

Validation and sanitization for the prefix component of a TypeID. Use [mti](https://crates.io/crates/mti) for complete identifiers, or combine this crate with [typeid_suffix](https://crates.io/crates/typeid_suffix).

## Installation

```toml
[dependencies]
typeid_prefix = "1.2"
```

## Validation

Parsing accepts 1 to 63 ASCII characters: lowercase letters and internal underscores. A parsed prefix must start and end with a lowercase letter. Input is validated without modification.

```rust
use typeid_prefix::{TypeIdPrefix, ValidationError};

let prefix = TypeIdPrefix::try_from("user_account").unwrap();
assert_eq!(prefix.as_str(), "user_account");
assert_eq!(TypeIdPrefix::try_from(""), Err(ValidationError::IsEmpty));
assert_eq!(TypeIdPrefix::try_from("Invalid"), Err(ValidationError::InvalidStartCharacter));
assert_eq!(TypeIdPrefix::try_from("_user"), Err(ValidationError::StartsWithUnderscore));
assert_eq!(TypeIdPrefix::try_from("user_"), Err(ValidationError::EndsWithUnderscore));
assert_eq!(TypeIdPrefix::try_from("a".repeat(64)), Err(ValidationError::ExceedsMaxLength));
```

`PrefixFactory` is available through the prelude:

```rust
use typeid_prefix::prelude::*;

let prefix = "user".try_create_prefix().unwrap();
assert_eq!(prefix.as_str(), "user");
assert!("user name".try_create_prefix().is_err());
```

The TypeID format permits an absent prefix. This crate's parsing methods reject empty input, while `TypeIdPrefix::default()` represents an empty prefix. Sanitization also returns this empty value when no valid prefix remains. Do not assume every value has passed parsing validation, especially values generated by the `arbitrary` feature.

## Sanitization

`create_prefix_sanitized()` lowercases the input, keeps at most the first 63 characters, removes characters other than ASCII lowercase letters and underscores, and trims leading and trailing underscores. Spaces are removed, not replaced with underscores. Truncation occurs before filtering, so invalid characters can consume part of the limit.

```rust
use typeid_prefix::prelude::*;

assert_eq!("Invalid String 123!@#".create_prefix_sanitized().as_str(), "invalidstring");
assert_eq!("_Another_Example_".create_prefix_sanitized().as_str(), "another_example");
assert_eq!("!@#$%^".create_prefix_sanitized(), TypeIdPrefix::default());
assert!(TypeIdPrefix::default().as_str().is_empty());
```

Sanitization can map different inputs to the same prefix. Use `try_create_prefix()` when invalid input must be rejected.

## Optional features

- `instrument`: logs a warning when sanitization falls back to an empty prefix. Configure a tracing subscriber in your application to collect these events.
- `serde`: serializes prefixes as strings and validates strings during deserialization. An empty default prefix serializes as `""`, but deserializing that string fails validation.
- `arbitrary`: derives `Arbitrary` for fuzzing. Generated values do not pass through prefix validation.

```toml
[dependencies]
typeid_prefix = { version = "1.2", features = ["serde", "instrument"] }
serde_json = "1"
```

```rust
# #[cfg(feature = "serde")] {
use typeid_prefix::TypeIdPrefix;

let prefix = TypeIdPrefix::try_from("user").unwrap();
let json = serde_json::to_string(&prefix).unwrap();
assert_eq!(json, "\"user\"");
assert_eq!(serde_json::from_str::<TypeIdPrefix>(&json).unwrap(), prefix);
assert!(serde_json::from_str::<TypeIdPrefix>("\"\"").is_err());
# }
```
